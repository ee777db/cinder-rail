# Contributing

Start with a narrow, reproducible problem. Include the expected behavior, observed behavior, runtime version and a minimal test using synthetic data. Run the application checks, HTTP tests for API changes and contract tests for Solidity changes before submitting a pull request.

Preserve the release's explicit trust model. Do not describe test credits as money, a provider signature as proof of correct inference, a sequencer acknowledgment as final settlement, or an undeployed contract as a live network. New payment schemes must be opt-in and separately tested.

Do not commit credentials, account identifiers, private signing keys, prompts from other people, `.dev.vars`, Wrangler state or exported session receipts. Report vulnerabilities privately through GitHub private vulnerability reporting if the repository owner enables it; otherwise use a minimal non-sensitive issue requesting a private channel. Do not post working exploits or secrets publicly.
